# Source-first sketch and asset workflow

Use this approach for the bridge and subsequent palace, building, garden, furniture and terrain sketches. Preserve saved originals. Keep reference images small and inspect one panel at a time.

1. Identify the selected original image and its stable ID, revision and SHA-256. Record alternate or superseded designs separately.
2. Save direct crops with descriptive filenames before opening them. Write an index with source ID, pixel bounds, title, hash and printed labels. Crops are reference extractions, not newly generated designs.
3. Inspect the named panels individually. Catalogue the visible components, their silhouettes, motifs, materials, backs/undersides where supplied, repetition and attachment relationships. Do not replace source parts with generic counterparts.
4. Compare a proposed pack against the source catalogue. Record omitted, changed, fused and invented parts. Distinguish user-requested supplemental parts from parts actually depicted in the selected source.
5. Record conflicting source views and dimensions. Do not turn a cross-section into a purportedly measured longitudinal module or assume hidden geometry is known.
6. Generate only missing references after the inventory exists. Existing adequate source panels are reused rather than regenerated. Correct an existing generated variant by binding its model target to the authoritative source crop wherever that crop already resolves the design. For actual gaps, use compact packs: 10–20 small components per ornament sheet, 3–4 principal component/segment types per structural sheet. Use one small original reference per generation where sufficient; a focused edit may need the small target and its exact replacement source. Do not load unrelated references.
7. Print an ID and a short name beside every generated object. Keep objects fully visible and separated. A single view per object usually leaves room for more components; extra underside or interface views are reserved for unresolved joins.
8. Retain component IDs when the component is corrected. Give newly discovered parts new IDs; do not silently repurpose an ID to mean another object. Preserve prior image revisions and model reference hashes.
9. Review the output against the inventory. Record remaining deviations honestly. A source-inspired drawing, a readable label or a batch generation is not evidence of accurate geometry or separate meshes.
10. Register returned 3D files by pack, component, revision, generator/job and hash. Check the actual component contents, proportions, material boundaries and attachment fit in Blender before marking a model reviewed or integrated.

For the bridge, the primary source is GEN-18. Its direct panel register and discrepancy report are in bridge-source-panels. The stepped lotus capital from MOD-COL-001 is a user-requested supplemental part; it is not claimed as a literal bridge-source crop. Glossy-deck ripples remain a runtime effect rather than a physical ornament.

Keep rose and ivory marble, the selected glass colours and the observed carving vocabulary consistent across sources. Numerical labels copied from illustrative art remain unverified until a coherent model layout resolves them.

## Structure correspondence before ornament

Matching palette and motifs is insufficient. Trace the actual source wing masses, tier offsets, great/medium/small window hierarchy, tower/pavilion attachments and stair axes before generating a replacement structural view. A decorated reinterpretation is still a rejected reference when that arrangement changes. Direct original crops are preferred until correspondence is established.
